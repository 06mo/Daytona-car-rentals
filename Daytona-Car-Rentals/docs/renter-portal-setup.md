# Renter portal setup and verification

This iteration is local-only. No hosted migration, Auth configuration, real email delivery, paid service or deployment was performed. Existing production, `mts-ag-services`, Preview protection and hosted records are untouched.

## Implemented boundaries

Public browsing/quotes remain available. Final request submission requires a Supabase-verified email session. The server calls Auth `getUser`, never trusts a reference/client email or decoded browser session, and uses the returned UUID for ownership. Access/refresh cookies are HttpOnly, SameSite=Lax and Secure in production. Logout revokes refresh sessions globally and clears local cookies; provider JWT expiry/revocation behavior needs hosted verification. Owner authentication retains the existing independent password/session mechanism. Audit actors identify customer UUIDs or owner session fingerprints, not individual owner employees.

A link opens a confirmation screen; a same-origin POST consumes the token, avoiding automatic sign-in by ordinary link scanners. A random, expiring private intent carries only vehicle/dates/period/pickup in the return path. No contact details, quote IDs or sensitive documents go into email URLs. Cross-device sign-in restores those trip fields; the customer recalculates an expired/unsaved quote and enters contact information after sign-in. Unsent name/phone fields are kept in tab session storage for up to 30 minutes, scoped to the verified account and cleared on submission/logout. They survive same-tab reauthentication but are deliberately not put in cross-device email links. Authentication never represents driver verification or rental approval. Expired/reused provider tokens surface a fresh-link prompt. The server limits sign-in requests per hashed email and globally; configure provider protections too.

Old guest requests require the reference plus a match against the **server-verified** email, followed by explicit owner review. A claim response reveals neither request details nor whether a record matched. The owner must check original records before approving a single association. No bulk email linking exists.

## Intake, retention and review

Intake collects legal name, birth date, issuing region, license expiry and agreement address with renter confirmation. No SSN, payment card, raw typed license number, OCR, external screening or agreement signing is added. JPEG/PNG only, 2 MB and 16 megapixels maximum; server decoding rejects malformed/multi-page/other formats and strips metadata. Images are private bytea records protected by forced RLS and ownership-checked, audited downloads with no-store and attachment headers. They are never public URLs, logs or email attachments. This design is bounded for Vercel’s request size and does not need a filesystem.

Document access expires 30 days after the requested return. Owner purge removes expired bytes; customers can delete earlier, invalidating required review. Physical cleanup requires the worker schedule above. Approve the legal/operational retention schedule, backup retention, and legal-hold process before real documents/live use. No automatic legal-hold process or malware-scanning provider is claimed. Only decoded/re-encoded images are accepted.

Contact completion, email account association, confirmed intake, document approval, manual license/MVR/insurance checks, eligibility approval, agreement/payment/protection evidence and final reservation confirmation are distinct. Eligibility approval is **approved/action required**, not confirmed. Existing release gates, fresh channel check, unexpired hold and serialized availability check remain mandatory. Decline releases the hold; corrections preserve it until expiry. Alternatives leave the original car unchanged until explicit customer acceptance of an unexpired, unchanged server quote and a fresh availability check. Agreement export maps reviewed fields and the quote snapshot; it is not a signed legal document.

## Settings and historical prices

Existing `config` settings/rate records are extended with validated policy fields; no competing settings store exists. Vehicle policy overrides global policy; explicit vehicle daily rate overrides the global daily default. Blank policy controls inherit. Base legacy settings remain fallback values. Seven-day prices apply to complete 7-day blocks plus daily remainder; 30-day price applies only to exactly 30 days. No implicit discount is created. Maximum term stays 30 days; renewal needs a new approved request and availability check.

Configured mileage, excess-mileage charges, age/duration limits, pickup/delivery fees, buffers, document requirements and operational terms are snapshotted with accepted quotes. Revisions invalidate open quotes, not accepted request prices. Old setting versions and actor/time audits are retained. Sample/demo values are not approved business policy; editable policy does not establish statutory or insurer requirements. The global Postgres transaction lock continues to serialize conflicting writes; notification claims and acknowledgments take that lock briefly, while external delivery runs outside it using expiring claims (migration 004). See `docs/renter-portal-review-fixes.md`.

## Local verification versus hosted verification

`npm test`, `npm run test:portal`, `npm run typecheck`, `npm run build`, and the Playwright suite use isolated local Postgres. Browser tests use a loopback HTTPS GoTrue **protocol fixture**, never real email or an application authentication bypass. Generated test keys/certificates are temporary outside Git and removed with the fixture. The fixture exercises the actual SDK/server routes, cookies, cross-device links and authorization, but cannot prove hosted Auth delivery, JWT revocation timing, redirect templates, SMTP, Vercel limits or provider configuration.

Hosted prerequisites include migration/RLS/Data API denial verification, first-time and returning magic-link delivery to approved test recipients only, invalid/used/expired tokens, logout/refresh across devices, exact origins through Vercel protection, and small synthetic image upload/download under hosted limits. No production or hosted-verified claims should be inferred from local tests. Stripe, Checkr Trust commercial/onboarding confirmation, OCR, legal agreement signing and live rentals remain separate.
